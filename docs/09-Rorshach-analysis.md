
# تحلیل آزمون رورشاخ

## مقدمه

آزمون رورشاخ (Rorschach Inkblot Test) یک آزمون فرافکنانه است که در آن فرد به مجموعه‌ای از لکه‌های جوهر پاسخ می‌دهد و پاسخ‌های او بر اساس ویژگی‌های مشخصی **کدگذاری، طبقه‌بندی و تحلیل** می‌شوند.

در پیاده‌سازی نرم‌افزاری آزمون رورشاخ، بهتر است بین سه مرحله تفاوت قائل شویم:

1. **ثبت پاسخ خام فرد**
2. **کدگذاری پاسخ بر اساس سیستم امتیازدهی**
3. **محاسبه شاخص‌ها و متغیرهای ترکیبی**

دو سیستم مهم در این زمینه عبارت‌اند از **Exner Comprehensive System (CS)** و **Rorschach Performance Assessment System (R-PAS)**. این دو سیستم مجموعه متغیرها و روش‌های محاسبه متفاوتی دارند و نباید کدهای آن‌ها بدون تطبیق با یکدیگر ترکیب شوند.

## 1. اطلاعات پایه هر پاسخ

در نرم‌افزار، برای هر پاسخ بهتر است اطلاعات اولیه زیر ذخیره شود:

| پارامتر            | توضیح                           |
| ------------------ | ------------------------------- |
| ‏`card`            | شماره کارت رورشاخ               |
| ‏`response_text`   | متن پاسخ فرد                    |
| ‏`response_time`   | مدت زمان پاسخ                   |
| ‏`card_turn`       | وضعیت چرخاندن کارت              |
| ‏`response_number` | شماره پاسخ                      |
| ‏`inquiry_data`    | اطلاعات مرحله پرسش و بررسی پاسخ |

این اطلاعات، داده‌های خام هستند و هنوز به‌تنهایی امتیاز روان‌شناختی محسوب نمی‌شوند.


# ‏2. Location — محل استفاده از لکه

این بخش مشخص می‌کند فرد از **کدام قسمت لکه جوهر** برای ارائه پاسخ استفاده کرده است.

| کد   | نام             | توضیح                              |
| ---- | --------------- | ---------------------------------- |
| `W`  | ‏Whole          | استفاده از کل لکه                  |
| `D`  | ‏Common Detail  | استفاده از یک جزئیات رایج          |
| `Dd` | ‏Unusual Detail | استفاده از جزئیات کوچک یا غیرمعمول |
| `S`  | ‏Space          | استفاده از فضای سفید               |

این متغیر نشان می‌دهد پاسخ بر اساس چه محدوده‌ای از محرک تصویری شکل گرفته است.

# ‏3. Determinants — عوامل تعیین‌کننده پاسخ

‏Determinants مشخص می‌کنند **چه ویژگی بصری لکه باعث شده فرد آن پاسخ را ارائه کند**.

مهم‌ترین گروه‌ها عبارت‌اند از:

### ‏Form

|کد|توضیح|
|---|---|
|`F`|شکل یا فرم لکه|

### ‏Movement

|کد|توضیح|
|---|---|
|`M`|حرکت انسانی|
|`FM`|حرکت حیوانی|
|`m`|حرکت غیرزنده / مکانیکی|

### ‏Color

|کد|توضیح|
|---|---|
|`C`|رنگ خالص|
|`CF`|رنگ غالب بر فرم|
|`FC`|فرم غالب بر رنگ|

### ‏Achromatic Color

|کد|توضیح|
|---|---|
|`C'`|رنگ‌های آکروماتیک مانند سیاه، خاکستری یا سفید|

### ‏Shading

|کد|توضیح|
|---|---|
|`T`|بافت / Tactile|
|`V`|سایه‌روشن با کیفیت عمق یا ارزش|
|`Y`|سایه‌روشن منتشر|

### سایر Determinants

بسته به سیستم کدگذاری، متغیرهایی مانند:

- ‏Reflection
- ‏Pair
- ‏Form Dimension
- سایر ترکیب‌های فرم، رنگ و سایه

نیز ممکن است ثبت شوند.


# ‏4. Form Quality — کیفیت فرم

Form Quality مشخص می‌کند که آیا شکل واقعی پاسخ با شکل موجود در لکه **تناسب قابل قبول** دارد یا خیر.

کدهای رایج عبارت‌اند از:

|کد|مفهوم کلی|
|---|---|
|`+`|کیفیت فرم بسیار مناسب|
|`o`|کیفیت فرم معمول / مناسب|
|`u`|کیفیت فرم نامشخص یا کمتر متناسب|
|`-`|کیفیت فرم ضعیف|
|`none`|در مواردی که کیفیت فرم قابل ارزیابی نیست|

این بخش یکی از قسمت‌های مهم کدگذاری است و باید بر اساس جدول‌ها و معیارهای رسمی همان سیستم امتیازدهی انجام شود.


# ‏5. Content — محتوای پاسخ

‏Content مشخص می‌کند **فرد چه چیزی را در لکه دیده است**.

گروه‌های مهم:

|کد|محتوا|
|---|---|
|`H`|انسان کامل|
|`Hd`|بخش‌هایی از انسان|
|`A`|حیوان|
|`Ad`|بخش‌هایی از حیوان|
|`An`|آناتومی|
|`Art`|هنر|
|`Ay`|انسان‌شناسی|
|`Na`|طبیعت|
|`Fd`|غذا|
|`Sex`|محتوای جنسی|
|`MOR`|محتوای آسیب‌دیده، مرده یا آسیب‌زا|

سیستم دقیق کدگذاری می‌تواند شامل دسته‌های بیشتری باشد.

# ‏6. Popular Responses — پاسخ‌های رایج

در بعضی سیستم‌ها بررسی می‌شود که آیا پاسخ فرد با یکی از **پاسخ‌های رایج و شناخته‌شده برای یک کارت یا ناحیه خاص** مطابقت دارد یا خیر.

این متغیر معمولاً به‌صورت یک مقدار منطقی یا کد اختصاصی ذخیره می‌شود:

```text
popular = true
```

یا:

```text
popular = false
```

البته تشخیص پاسخ رایج باید بر اساس جدول رسمی سیستم مورد استفاده انجام شود.

# ‏7. Special Scores — نمره‌های ویژه

‏Special Scores برای شناسایی ویژگی‌های خاص در ساختار پاسخ استفاده می‌شوند.
نمونه‌های مهم:

| کد              | مفهوم                         |
| --------------- | ----------------------------- |
| ‏`DV` / `DV2`   | انحراف کلامی                  |
| ‏`DR` / `DR2`   | پاسخ‌گویی یا استدلال غیرمعمول |
| ‏`INC` / `INC2` | ناسازگاری                     |
| ‏`FABCOM`       | ترکیب ساختگی                  |
| ‏`ALOG`         | منطق نامعمول                  |
| ‏`CONTAM`       | آلودگی / ترکیب نامتعارف       |
| ‏`PER`          | ‏ویژگی شخصی‌سازی‌شده پاسخ     |
| ‏`PSV`          | ‏Perseveration                |
| ‏`MOR`          | محتوای آسیب‌دیده یا منفی      |

تعداد و تعریف دقیق این کدها به سیستم امتیازدهی وابسته است.

# ‏8. Organizational Activity — فعالیت سازمان‌دهی

این دسته بررسی می‌کند فرد چگونه اجزای لکه را در یک ساختار کلی سازمان‌دهی کرده است.

در سیستم Exner متغیرهایی مانند موارد زیر وجود دارند:

|کد|توضیح|
|---|---|
|`Zf`|تعداد پاسخ‌هایی که دارای فعالیت سازمان‌دهی هستند|
|`ZSum`|مجموع امتیازهای سازمان‌دهی|
|`ZEst`|برآورد مرتبط با فعالیت سازمان‌دهی|

این متغیرها معمولاً در سطح کل پروتکل محاسبه می‌شوند، نه صرفاً یک پاسخ منفرد.

# 9. تعداد پاسخ‌ها

تعداد پاسخ‌های ارائه‌شده نیز یک متغیر مهم است:

```text
R = Total Number of Responses
```

برای مثال:

```json
{
  "R": 23
}
```

در تحلیل‌های بعدی، تعداد پاسخ‌ها می‌تواند در محاسبه یا تفسیر برخی شاخص‌ها نقش داشته باشد.


# 10. شاخص‌های مرتبط با فرم

از ترکیب کدهای فرم، شاخص‌های دیگری نیز محاسبه می‌شوند.

نمونه‌های مهم:

### ‏F%

درصد پاسخ‌هایی که Determinant اصلی آن‌ها فرم است.

### ‏Pure F%

درصد پاسخ‌هایی که صرفاً بر اساس فرم هستند و عوامل دیگری مانند حرکت یا رنگ در آن‌ها دخالت ندارند.

این شاخص‌ها معمولاً برای بررسی نحوه استفاده فرد از ویژگی‌های ساختاری محرک به کار می‌روند.


# 11. شاخص‌های مرتبط با حرکت

متغیرهایی مانند:

```text
M
FM
m
```

به‌ترتیب اطلاعات مربوط به:

- حرکت انسانی
- حرکت حیوانی
- حرکت مکانیکی یا غیرزنده

را در اختیار سیستم قرار می‌دهند.

این مقادیر معمولاً در سطح کل پروتکل جمع‌آوری و در شاخص‌های ترکیبی استفاده می‌شوند.


# 12. شاخص‌های مرتبط با رنگ

بر اساس پاسخ‌ها می‌توان متغیرهایی مربوط به استفاده از رنگ نیز محاسبه کرد.

نمونه‌ها:

```text
C
CF
FC
WSumC
Afr
```

یکی از شاخص‌های مهم **WSumC** است که از وزن‌دهی به پاسخ‌های رنگی بر اساس قواعد سیستم محاسبه می‌شود.


# 13. شاخص‌های مرتبط با سایه

گروه دیگری از متغیرها به استفاده از shading مربوط می‌شوند:

```text
T
V
Y
```

این متغیرها می‌توانند در محاسبه شاخص‌های ترکیبی مرتبط با تجربه فشار، استرس و واکنش به محرک‌های پیچیده مورد استفاده قرار گیرند.


# 14. شاخص‌های محاسباتی مهم

برخی متغیرها مستقیماً از یک پاسخ استخراج نمی‌شوند و باید پس از کدگذاری **کل پروتکل** محاسبه شوند.

نمونه‌های مهم:

|شاخص|توضیح کلی|
|---|---|
|`Lambda`|نسبت مشخصی از پاسخ‌های فرم‌محور|
|`EA`|Experience Actual|
|`es`|Experience Stimulation|
|`WSumC`|Weighted Sum of Color|
|`Afr`|Affective Ratio|
|`Egocentricity Index`|شاخص خودمحوری|
|`PTI`|شاخص اختلالات ادراکی/تفکری|
|`HVI`|Hypervigilance Index|
|`Isolation Index`|شاخص انزوا|
|`Intellectualization`|شاخص Intellectualization|
|`XA%`|شاخص کیفیت ادراکی فرم|
|`WDA%`|کیفیت فرم در پاسخ‌های W و D|
|`Complexity`|پیچیدگی پاسخ‌ها|

نکته مهم این است که **این مقادیر را نباید مستقیماً از متن پاسخ حدس زد**؛ ابتدا باید پاسخ به‌صورت استاندارد کدگذاری شود و سپس شاخص مربوطه طبق فرمول همان سیستم محاسبه شود.


# ‏15. R-PAS

سیستم **Rorschach Performance Assessment System (R-PAS)** رویکرد جدیدتری برای کدگذاری و تفسیر آزمون رورشاخ است و متغیرهای آن در چند حوزه اصلی سازمان‌دهی می‌شوند.

‏Rorschach Performance Assessment System

چهار حوزه اصلی R-PAS عبارت‌اند از:

### ‏1. Engagement and Cognitive Processing

مربوط به نحوه درگیر شدن فرد با محرک و پردازش اطلاعات.

نمونه متغیرها:
- ‏Complexity
- تعداد پاسخ‌ها
- ‏F%
- شاخص‌های پردازش شناختی

### ‏2. Perception and Thinking Problems

مرتبط با نحوه ادراک و سازمان‌دهی اطلاعات و ویژگی‌های غیرمعمول در تفکر.

### ‏3. Self and Other Representation

مرتبط با نحوه بازنمایی خود و دیگران در پاسخ‌ها.

### ‏4. Stress and Distress

مرتبط با متغیرهایی که به تجربه و مدیریت فشار یا پریشانی مربوط می‌شوند.

‏R-PAS همچنین مجموعه‌ای از متغیرهای مربوط به **رفتار هنگام اجرای آزمون و مشاهده‌های اجرایی** را نیز در نظر می‌گیرد.

# 17. جریان کلی تحلیل

در یک نرم‌افزار تحلیل رورشاخ، جریان منطقی بهتر است به شکل زیر باشد:

```text
پاسخ فرد
    ↓
ثبت پاسخ خام
    ↓
کدگذاری پاسخ
    ↓
Location
Determinants
Form Quality
Content
Special Scores
    ↓
تجمیع کل پاسخ‌ها
    ↓
محاسبه شاخص‌ها
    ↓
ساخت پروفایل آزمون
    ↓
تفسیر توسط سیستم مربوطه
```

به عبارت ساده‌تر:

>‏ **Raw Response → Coding → Variables → Calculated Scores → Profile → Interpretation**


## 18. نکته مهم در طراحی سیستم

برای یک پروژه نرم‌افزاری، بهتر است **داده خام، کدگذاری و تفسیر از یکدیگر جدا باشند**.

مثلاً:

```json
{
  "card": 3,
  "response_text": "دو انسان که روبه‌روی هم ایستاده‌اند",
  "response_time": 18,
  "coding": {
    "location": "W",
    "determinants": ["M", "F"],
    "form_quality": "o",
    "content": ["H"],
    "popular": false,
    "special_scores": []
  }
}
```

سپس نرم‌افزار می‌تواند از مجموع چنین پاسخ‌هایی متغیرهای سطح پروتکل را محاسبه کند:

```text
R
F%
PureF%
M
FM
m
WSumC
EA
es
XA%
WDA%
Complexity
...
```

### نکته کلیدی
کدگذاری رورشاخ **سیستم‌وابسته** است. بنابراین در طراحی دیتابیس بهتر است مشخص شود آزمون بر اساس کدام سیستم کدگذاری انجام شده است: ما از r-pas در این سیستم استفاده می کنیم.
